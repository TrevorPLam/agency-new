# `firm-cache` — Package Planning Document

**Tenant‑Scoped Redis · Tag‑Based Invalidation · Wrapper over `ioredis` · Cache Key Factories · Structural Helpers · Explicit Caching Lifecycle**

---

## 0. Purpose & Architectural Position

`firm-cache` is the **sole entry point for all caching operations** in the platform. It provides a tenant‑scoped Redis client, factory functions for constructing cache keys that embed `tenantId`, tag‑based invalidation, and structural helpers for common caching patterns (e.g., `cachedFunction`, `cacheThrough`).

All higher layers use `firm-cache` instead of raw Redis clients. Feature packages (Layer 6) declare their cache lifecycles and tags using this package’s primitives; raw string concatenation for cache keys is forbidden.

**Layer placement:** Layer 2, Wave 3 — built fifth, after `firm-db`. Depends on `firm-types` (branded IDs, tenant identity) and `firm-env` (validated Redis connection string). Contains **no business logic** — only key factories, ttl policies, and invalidation helpers.

**What it owns:**

| Domain | Mechanism |
|---|---|
| Cache key generation | Factory functions: `cacheKey(tenantId, domain, ...segments)` returns a namespaced, tenant‑prefixed key |
| Tag‑based invalidation | Associates keys with tags (stored in Redis Sets), allows bulk invalidation by tag |
| Connection management | Creates and exposes a tenant‑scoped `ioredis` client (or a cluster of clients) from validated environment variables |
| Structural helpers | `withCache(key, ttl, fetch)`, `invalidateTags(tags)`, `cachedPipeline()` |
| Cache lifecycle policies | Named TTL constants for common data categories (session, entity, query) |

**2026 context:** Redis 7.4 is the current stable (with functions and enhanced pub/sub). `ioredis` v5 is the leading TypeScript Redis client, fully supporting Redis 7, Cluster, Sentinel, and TLS. Supabase provides managed Redis via their add‑on, but the package is provider‑agnostic — only a connection URL is required.

## 1. Immutable Rules

| Rule | Rationale |
|---|---|
| **All cache keys are generated by factory functions — never raw string concatenation.** | Guarantees tenant isolation; prevents key collisions across tenants; enables centralised key format governance. |
| **Every cache key is prefixed with `tenantId`.** | `firm-cache` automatically scopes all operations to the current tenant. No other package may inject arbitrary prefixes. |
| **Tag‑based invalidation is the only invalidation mechanism exposed to feature packages.** | Prevents “scan and delete” anti‑patterns; tags are the contract for cache lifecycle management. |
| **No business logic.** Only key factories, ttl policies, and invalidation helpers. | Feature packages import `firm-cache` for caching patterns, not business rules. |
| **Connection strings come from `firm-env` validated environment variables.** | No hardcoded URLs, no fallback to `localhost`. |
| **`exports` field is the sole contract boundary.** | Only `src/index.ts` reachable from outside. |
| **Named exports only. No default exports.** | Consistent import patterns. |
| **PII never reaches Redis without hashing.** | If a cache key or value might contain personal data, it must be hashed or encrypted before storage. The factory functions enforce this for known PII fields. |
| **No infinite TTL.** All keys must have a TTL defined via named policy. `EXPIRE` 0 or permanent keys are forbidden. | Prevents stale data accumulation and makes cache lifecycle explicit. |

## 2. Tenant Isolation via Key Scoping

Every cache operation is performed through a scoped client that automatically prefixes keys with the current `tenantId`. The core pattern:

```typescript
// packages/firm-cache/src/client.ts
import { Redis } from 'ioredis';
import type { TenantId } from 'firm-types';

export class TenantCache {
  constructor(
    private readonly redis: Redis,
    private readonly tenantId: TenantId,
  ) {}

  async get(key: string): Promise<string | null> {
    return this.redis.get(this.scope(key));
  }

  async set(key: string, value: string, ttlSeconds?: number): Promise<void> {
    await this.redis.set(this.scope(key), value, 'EX', ttlSeconds ?? 300);
  }

  async del(key: string): Promise<void> {
    await this.redis.del(this.scope(key));
  }

  // ... other Redis commands, all scoped
  private scope(key: string): string {
    return `tenant:${this.tenantId}:${key}`;
  }
}
```

Feature packages never instantiate `TenantCache` directly; they obtain a scoped instance via `createTenantCache(tenantId)`.

## 3. Cache Key Factory

Raw strings are banned. All keys are built using the `cacheKey()` factory:

```typescript
// packages/firm-cache/src/key-factory.ts
import type { TenantId } from 'firm-types';

export type CacheDomain = 'session' | 'user' | 'tenant-config' | 'lead' | 'booking' | 'analytics' | 'query';

export function cacheKey(
  tenantId: TenantId,
  domain: CacheDomain,
  resourceId: string,
  subResource?: string,
): string {
  // Internally scoped: tenant:{tenantId}:domain:{resourceId}[:subResource]
  const scope = `tenant:${tenantId}:${domain}`;
  return subResource ? `${scope}:${resourceId}:${subResource}` : `${scope}:${resourceId}`;
}
```

**Additional helper for composite keys:**

```typescript
export function cacheKeyFromParts(
  tenantId: TenantId,
  domain: CacheDomain,
  parts: string[],
): string {
  return `tenant:${tenantId}:${domain}:` + parts.join(':');
}
```

**Linting rule:** `no-restricted-syntax` in ESLint configuration prevents direct string interpolation for cache keys. Only `cacheKey()` and `cacheKeyFromParts()` are allowed.

## 4. Tag‑Based Invalidation

### 4.1 Mechanics

Tags are stored as Redis Sets. When a key is set, it is added to all tag sets it belongs to. Invalidation by tag retrieves all keys in the set and deletes them.

```typescript
// packages/firm-cache/src/tags.ts
export class TagManager {
  constructor(private readonly cache: TenantCache) {}

  async tagKey(key: string, tags: string[]): Promise<void> {
    const pipeline = this.cache.pipeline();
    for (const tag of tags) {
      pipeline.sadd(this.tagKeyName(tag), key);
    }
    await pipeline.exec();
  }

  async invalidateTags(tags: string[]): Promise<void> {
    const pipeline = this.cache.pipeline();
    for (const tag of tags) {
      const tagKey = this.tagKeyName(tag);
      const keys = await this.cache.smembers(tagKey);
      if (keys.length > 0) {
        pipeline.del(...keys);
        pipeline.del(tagKey);
      }
    }
    await pipeline.exec();
  }

  private tagKeyName(tag: string): string {
    return `tag:${tag}`; // Not tenant‑scoped? Yes, tags are global across tenants or per‑tenant? We'll discuss.
  }
}
```

**Design decision:** Tags can be **tenant‑scoped** or **global**. For most use cases, tags are tenant‑scoped (e.g., “leads” for tenant A vs tenant B). The `TagManager` will prefix tags with `tenant:${tenantId}:tag:...` to avoid cross‑tenant invalidation. This aligns with isolation rules.

### 4.2 Invalidation Patterns

| Pattern | Description | When to Use |
|---|---|---|
| `invalidateTag('leads')` | Bulk-invalidate all cached lead‑related data | After bulk import, schema change, or campaign update |
| `invalidateTag('tenant:config')` | Clear tenant configuration cache | After tenant settings update |
| `invalidateTags(['user:123', 'session:xyz'])` | Invalidates multiple entities | After user deletion, logout, or session revocation |

## 5. Structural Helpers

### 5.1 `withCache()`

The general‑purpose fetch‑through cache:

```typescript
export async function withCache<T>(
  cache: TenantCache,
  tags: string[],
  key: string,
  ttlSeconds: number,
  fetch: () => Promise<T>,
): Promise<T> {
  const cached = await cache.get(key);
  if (cached) return JSON.parse(cached) as T;

  const fresh = await fetch();
  await cache.set(key, JSON.stringify(fresh), ttlSeconds);
  if (tags.length > 0) {
    await cache.tagManager.tagKey(key, tags);
  }
  return fresh;
}
```

### 5.2 `invalidateTags()` (public helper)

Wraps the tag manager for easy use:

```typescript
export function invalidateTags(cache: TenantCache, tags: string[]) {
  return cache.tagManager.invalidateTags(tags);
}
```

### 5.3 `cachedPipeline()`

For batched operations that need to invalidate tags atomically:

```typescript
export function cachedPipeline(cache: TenantCache, operations: Array<() => Promise<void>>) {
  const pipeline = cache.pipeline();
  // ... execute operations within a MULTI/EXEC ...
}
```

## 6. Named TTL Policies

All TTLs are defined as named constants, never inline numbers:

```typescript
// packages/firm-cache/src/ttl-policies.ts
export const CACHE_TTL = {
  // Session data (sensitive, short‑lived)
  session: 900,           // 15 minutes
  // User profile (stable, refreshed on login)
  userProfile: 3600,      // 1 hour
  // Tenant configuration (changes rarely)
  tenantConfig: 7200,     // 2 hours
  // Database query results (eventually consistent)
  queryResult: 300,       // 5 minutes
  // Rate‑limit counters (must be short to avoid lockout)
  rateLimit: 60,          // 1 minute
  // Feature flag evaluation
  featureFlag: 120,       // 2 minutes
  // Static data (marketing copy, navigation)
  staticData: 86400,      // 24 hours
} as const;
```

Feature packages must import `CACHE_TTL` and use these names — inline numbers trigger a lint error.

## 8. Key Patterns

### 8.1 Creating a Tenant‑Scoped Cache

```typescript
// In feature package (Layer 6) or during request initialization

const tenantId = asTenantId('d4a3b2c1-...');

```

### 8.2 Caching a Database Query

```typescript
import { cacheKey, withCache, invalidateTags, CACHE_TTL } from 'firm-cache';

const key = cacheKey(tenantId, 'lead', leadId);

const leadData = await withCache(cache, ['leads'], key, CACHE_TTL.queryResult, async () => {
  return await db.query.leads.findFirst({
    where: eq(leads.id, leadId),
  });
});
```

### 8.3 Invalidating After Mutation

```typescript
// After a lead is updated
await invalidateTags(cache, ['leads', `lead:${leadId}`]);
```

### 8.4 Cache‑Through for Tenant Configuration

```typescript
export async function getTenantConfig(cache: TenantCache, tenantId: TenantId) {
  const key = cacheKey(tenantId, 'tenant-config', 'main');

    return loadTenantConfigFromDb(tenantId);
```

## 10. Test Strategy

### 10.1 Unit Tests

| Subject | Assertions |
|---|---|
| `cacheKey()` | Produces deterministic, correctly prefixed keys. Fails with invalid inputs. |
| `TenantCache` scoping | All get/set/del operations are restricted to the tenant’s namespace. |
| `TagManager` | `tagKey()` adds keys to sets; `invalidateTags()` deletes all tagged keys and the tag set. |

- Connection to actual Redis, set/get/del.
- Tag invalidation under concurrent access.
- TTL expiration (using sleep).
- Failure handling (Redis down, timeout).

## 11. Connection Management

`createTenantCache(tenantId)` internally creates an `ioredis` client. The client is instantiated once per process and reused (singleton), unless a specific pattern requires a fresh client per request (serverless). The factory reads the connection URL from `firm-env`:

```typescript
import { getRedisUrl } from 'firm-env';
import { Redis } from 'ioredis';

let client: Redis | null = null;

function getClient(): Redis {
  if (!client) {
    client = new Redis(getRedisUrl(), {
      maxRetriesPerRequest: 3,
      enableOfflineQueue: false,
      lazyConnect: false,
    });
  }
  return client;
}

export function createTenantCache(tenantId: TenantId): TenantCache {
  return new TenantCache(getClient(), tenantId);
}
```

**For serverless environments (Vercel, Lambda):** A separate factory `createServerlessTenantCache` uses connection pooling or per‑request clients with a max lifetime to avoid stale connections. This is provided via an environment check, not a separate mode constant.

## 13. Interface Freeze & Governance

- After Wave 3, the `CacheDomain` union and `cacheKey()` signature are frozen. Adding a new domain is minor.
- TTL values may be adjusted (minor) but require documentation update and performance review.
- The `TenantCache` public interface is frozen; internal improvements (e.g., migrating to `ioredis` cluster) are transparent to consumers.
- CI checks that no raw string concatenation for cache keys appears in feature packages (ESLint rule).
